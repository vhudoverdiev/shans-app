# Shans

Flask веб-приложение для личного управления данными.

## Возможности

- Авторизация пользователей
- Учёт бюджета
- История баланса
- Экспорт бюджета в Excel
- Учёт выполненных работ по автомобилю
- Учёт планируемых работ по автомобилю
- Уведомления по обслуживанию автомобиля
- Раздел фотопроектов: город/адрес, временные окна и записи с оплатой

## Технологии

- Python
- Flask
- Flask-Login
- SQLite
- openpyxl
- Gunicorn
- Nginx
- systemd

## Отправка изменений в GitHub

Команда `deployshans` отправляет текущую ветку только в `https://github.com/vhudoverdiev/shans-app`.
Она создаёт коммит при наличии изменений и отправляет ранее созданные коммиты даже при чистой рабочей папке.
Видео AI-курса и аудио подкастов хранятся через Git LFS. Перед клонированием или обновлением проекта
на компьютере и сервере установите Git LFS (`brew install git-lfs` на macOS, `apt install git-lfs` на Ubuntu),
затем выполните `git lfs install` и `git lfs pull` в папке проекта. LFS загружает реальные медиафайлы вместо указателей.
Отправка в GitHub не запускает обновление сервера: для этого используется `deployservershans`.

## Уведомления

- Уведомления личного графика доставляются через Web Push в установленное на экран «Домой» веб-приложение.
- Сводка приходит в 10:00 за текущий день и в 20:00 за следующий день по московскому времени.
- Для задач с указанным временем отдельное напоминание приходит за 2 часа.
- Внешний скрипт или Telegram-бот, который уже отправляет сообщение в Telegram, может продублировать его в push на сайте через `POST https://shansplanner.ru/api/push/external/telegram`.
- На сервере нужно задать `TELEGRAM_PUSH_SECRET` в `.env`, а в запросе передавать тот же секрет в заголовке `X-Shans-Push-Secret`.
- Внешний Telegram-push всегда доставляется только основному системному администратору, созданному через `create_admin.py`; `username` и `user_id` в запросе не нужны.

Куда внести данные:

- `.env` на сервере с CRM: `TELEGRAM_PUSH_SECRET=длинный_случайный_секрет`.
- Окружение сервера, где работает Telegram-бот: тот же `TELEGRAM_PUSH_SECRET`.
- Если CRM доступна не по `https://shansplanner.ru`, добавьте рядом с ботом `CRM_TELEGRAM_PUSH_URL=https://ваш-домен/api/push/external/telegram`.

Пример запроса из скрипта:

```bash
curl -X POST "https://shansplanner.ru/api/push/external/telegram" \
  -H "Content-Type: application/json" \
  -H "X-Shans-Push-Secret: $TELEGRAM_PUSH_SECRET" \
  -d '{
    "title": "Шанс - Telegram",
    "body": "Бот прислал новое уведомление.",
    "navigate_path": "/"
  }'
```

Готовый Python-клиент можно импортировать прямо в код бота:

```python
from telegram_crm_push import send_crm_push


def notify_admin(text):
    # здесь остаётся ваша текущая отправка сообщения в Telegram
    # bot.send_message(chat_id=ADMIN_CHAT_ID, text=text)
    send_crm_push(text, title="Шанс - Telegram", navigate_path="/")
```

Или проверить вручную с сервера:

```bash
python telegram_crm_push.py "Проверка push из Telegram-бота"
```

## Деплой на сервер (main)

Если на сервере нет `deploy.sh`, значит локальный серверный репозиторий ещё не подтянут до коммита, где он добавлен.

```bash
cd /var/www/shans-app
git fetch origin
git checkout main
git reset --hard origin/main
```

Проверка, что скрипт появился:

```bash
ls -l /var/www/shans-app/deploy.sh
```

Запуск деплоя:

```bash
cd /var/www/shans-app
chmod +x deploy.sh
./deploy.sh
```

По умолчанию скрипт не удаляет `.env` (режим `CLEAN_MODE=safe`).
Также по умолчанию включена проверка чистоты tracked-файлов после деплоя (`VERIFY_CLEAN=true`).

Если после рестарта сервиса снова появляются изменения в `git status`, это признак того, что в репозитории по ошибке отслеживаются runtime-файлы (например, `__pycache__`, `*.pyc`, `logs/*`).

## Подкасты

В «Развитие → Подкасты» доступны категории IT, Саморазвитие и English.
Каталог записей находится в `app/podcast_content.py` (`PODCASTS`). Для каждой записи
задаются `slug`, `category` (`it`, `self-development` или `english`), `title`, `description`
и `filename` — путь относительно `app/podcast_media/`. Slug должен быть уникальным
внутри категории. Аудиофайлы размещаются в `app/podcast_media/`, вне публичной статики.
Поддерживаются MP3, M4A, OGG, WAV, AAC и MP4; для широкой совместимости предпочтителен MP3.

Страница записи позволяет слушать аудио встроенным плеером или скачать исходный файл.
Доступ к страницам и файлам требует входа и разрешения на раздел обучения.
Если файл отсутствует, страница сообщает о недоступности записи.
Пока каталог пуст, все категории показывают сообщение об отсутствии подкастов.

## Курс AI в разработке

В «Развитие → IT» доступен отдельный курс по авторскому ролику
`https://www.youtube.com/watch?v=1XIuYoHev-Y`: 17 смысловых видеоуроков,
конспект, практическое задание и три вопроса после каждого фрагмента.
Для открытия следующего урока нужны три правильных ответа.
Прогресс хранится отдельно от других курсов в `ai_course_progress`.
Материалы и таймкоды находятся в `app/ai_course_content.py`,
локальные H.264/AAC-фрагменты — в `app/static/videos/ai-development/`.

Добавленные подкасты хранят исходный YouTube ID и границы фрагмента.
Первый большой урок English и аудиокнига «Стань новым человеком» разбиты
на последовательные части с переходами между ними. Аудио хранится
в `app/podcast_media/`, доступ к прослушиванию и скачиванию проверяется сервером.
При переносе сайта необходимо переносить и локальные медиафайлы.
